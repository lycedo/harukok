# 로또 번호 생성기 개편 — 법률 검토 요청 문서 (2026-09-30)

이 문서는 외부 법률 검토에 전달하기 위해 작성했습니다. 하루콕 운영자가 내부적으로 정리한 자료이며,
**"자체 디자인·면책문구를 적용했으니 법적으로 문제없다"는 결론을 내리는 문서가 아닙니다.**
아래 기능은 로컬 환경(`fun/lotto-generator.html`)에 구현과 검증까지 마친 상태이며(2026-10-01, §7 참고),
이 문서의 검토와 법률 확인이 끝나기 전까지 dev 미리보기·운영 사이트(harukok.com) 어디에도 배포하지 않습니다.

## 1. 배경

- 대상: `/fun/lotto-generator` (기존 URL·기록·기능 보존)
- 변경 요지: 기존 "1게임 뽑기" 버튼을 "줄 수(1~5줄) 선택 → 번호 생성"으로 바꾸고,
  결과를 하루콕 자체 디자인의 종이형 "번호 메모"로 보여주며, 이미지 저장·텍스트 복사·공유 링크 기능을 추가.
- 실제 결제·충전·구매대행·번호 판매·경품(현금·상품) 지급 기능은 없음. 줄 수 선택은 한 번에 몇 줄을 생성할지
  정하는 UI일 뿐, 금액·포인트 등 돈을 연상시키는 표현은 전혀 쓰지 않음(2026-10-02 "가상 금액(원)" 표기 자체를
  제거하고 순수 줄 수 선택으로 단순화 — §2.1, §7 참고).
- 이용자에게 번호 생성 비용을 받지 않으며, 사이트는 광고 수익화를 계획합니다. "무료 제공"은 이용자가 이 도구를 쓰는 데
  대가를 지불하지 않는다는 뜻이며, 하루콕이 비영리로 운영된다는 의미가 아닙니다. 하루콕은 Google AdSense 광고 게재를
  통한 수익화를 목표로 하는 상업적 웹사이트입니다.

## 2. 기능 명세 (로컬 구현 기준)

### 2.1 입력·생성
- 줄 수 선택 5단계: 1 / 2 / 3 / 4 / 5줄, 가로 5열 그리드로 한 화면에 나란히 표시(2026-10-02부터 금액 표기
  없이 줄 수만 직접 선택 — 이전에는 "가상 금액(1,000~5,000원) 선택"으로 줄 수를 간접 표현했으나, 돈을 연상시키는
  표현 자체를 없애기 위해 단순화함).
- 각 줄: 1~45 중 서로 다른 정수 6개, 오름차순 정렬. 각 줄은 독립적으로 생성되며, 같은 묶음 안에서 줄끼리 우연히 같은 조합이 나올 수 있음(별도의 중복 방지 로직은 없음). 과거 기록과의 동일 조합도 허용.
- 버튼 라벨: "번호 생성" (구매/결제/발권 문구 사용하지 않음).
- 결제·충전·잔액 차감 로직 없음 — 줄 수는 UI 표시 값일 뿐 서버·클라이언트 어디에도 금액·잔액으로 저장되지 않음.
- (2026-10-02 추가) 화면 전체에서 "결제"라는 단어 자체를 없앴습니다. "무료 · 실제 결제 없음" 알약 라벨을
  "무료"로 줄이고, "~은 실제 결제와 무관하다"는 설명 문장과 그에 대응하는 FAQ 항목("1~5줄 선택은 실제 결제와
  관련 있나요?")을 삭제했습니다(FAQ 5개→4개, 화면 표시와 FAQPage 구조화 데이터 모두 동일하게 반영). 애초에
  결제를 암시하는 표현이 없으니 "결제와 무관하다"는 해명 자체가 불필요하다는 판단입니다. "실제 복권 아님 ·
  구매 및 당첨금 청구 효력 없음" 면책 문구는 결제가 아니라 "진짜 복권이 아니다"라는 취지라 그대로 유지합니다.

### 2.2 결과 표시
- 하루콕 자체 디자인의 "번호 메모" 카드: 상단 "하루콕 번호 메모", 행별 번호, 하단 "N줄 · 무료 생성"(금액 표기 없음).
- 공식 복권의 발행/추첨/판매점/당첨금 청구 서식(일련번호, 검증 바코드, 발권번호, 회차 표기 등)을 재현하지 않음.
- 화면과 저장 이미지·공유 텍스트 모두에 다음 문구를 항상 표시:
  **"하루콕 무료 번호 생성 결과 · 실제 복권 아님 · 구매 및 당첨금 청구 효력 없음"**
- (2026-10-02 변경) 번호 메모 카드 부제는 "harukok.com · 동행복권과 무관" 대신 날짜·시간만 표시(생성 시점의 "M/D HH:MM", 상세 모달도 저장 당시 같은 형식, 공유 열람은 "공유된 결과"). 카드 안의 "동행복권과 무관" 문구는 사라졌고, 이 취지는 카드 하단 면책 박스("실제 복권 아님 · 구매 및 당첨금 청구 효력 없음")와 FAQ("동행복권과 무관한 하루콕의 자체 서비스")에만 남음 — 운영자 요청에 따른 변경이며 법적 검토 시 이 점을 함께 판단받아야 함.
- AI 당첨 예측, 확률 향상, 당첨 보장, 공식 제휴로 오해할 수 있는 표현 사용하지 않음.

### 2.3 기록 호환
- 기존 `localStorage` 키(`harukok-lotto-history`)와 기존 레코드 구조(`{nums:number[6], date}`, 1줄 단위)를 계속 읽고 표시.
- 신규 저장 형식(묶음 단위, 1~5줄)으로 확장하되 최소한의 하위 호환 처리 포함 — 기존 레코드를 삭제·강제 변환하지 않음.
- **최근 생성 기록 목록**: 기록마다 생성 날짜·시간, 줄 수를 한 줄로 보여주는 간결한 목록(행 전체가
  클릭 가능한 버튼). 기존 1줄 기록과 신규 묶음 기록을 "N줄"로 같은 형식(금액 표기 없음)으로 통일해 표시하며, 공
  아이콘·개별 "다시 보기" 버튼은 목록에 두지 않음. 기본은 최근 5건만 보이고 "기록 더 보기"로 나머지를 펼침.
- **기록 상세 모달**: 행을 클릭하면 네이티브 `<dialog>`(`showModal()`) 모달이 열려 원래 생성 날짜·전체 번호를
  표시("저장된 기록 · 원래 생성일 M/D HH:MM"). 재추첨하거나 기록을 다시 저장하지 않으며(중복 추가 없음), 본문에
  표시 중인 "현재 생성 결과"와는 별도의 상태를 쓰므로 모달을 열어도 본문 내용이 바뀌지 않음. 모달 안에서도 이미지
  저장·텍스트 복사·공유가 모달이 보여주는 바로 그 기록을 대상으로 동작함. 기존 1줄 기록도 같은 모달로 열람 가능.
  데스크톱은 중앙 모달, 모바일은 화면 폭에 맞춘 모달(내용이 길면 내부 스크롤)로 표시되고, 닫기 버튼·ESC로 닫을 수
  있으며 열 때 포커스가 모달로 이동하고 닫으면 포커스가 원래 클릭한 행으로 돌아감. 모달이 열려 있는 동안 배경
  스크롤은 막힘. 새 라이브러리 없이 브라우저 기본 `<dialog>` 기능만 사용.

### 2.4 저장·복사·공유
- **이미지로 저장**: 화면에 표시된 묶음 전체(1~5줄)와 면책 문구가 포함된 이미지 생성.
- **텍스트 복사**: (2026-10-02 변경) 번호만 복사 — 줄마다 번호 6개를 공백으로 구분하고 줄은 줄바꿈으로 연결, 제목·줄 수·면책 문구 등 다른 텍스트는 포함하지 않음. 저장 이미지와 화면에는 면책 문구가 그대로 있음.
  - 형식 예시(2줄): `3 11 22 28 34 41` ⏎ `7 14 19 25 33 45`
- **공유 링크**: URL fragment(`#` 뒤)에 번호 묶음 데이터(JSON을 `encodeURIComponent`로 인코딩)만 담아 서버에는 전혀 저장하지 않는 방식으로 구현함. 공유 링크를 연 사람에게는:
  - "공유된 결과입니다 · 열람만 가능" 배지 표시.
  - 열람 시 재추첨하지 않음 (표시된 번호 그대로).
  - 방문만으로 열람자의 로컬 기록을 덮어쓰지 않음.
  - 유효 묶음 수(1~5)·번호 범위(1~45)·중복 여부를 파싱 시 검증하고, 값이 올바르지 않으면 안전하게 오류 처리.
  - 개별 공유 링크는 sitemap에 넣지 않고 `canonical`은 기본 생성기 주소로 유지.
  - 공유 화면에서는 "이미지로 저장"만 제공 — 열람자의 로컬 기록에 추가하거나 재공유용 새 링크를 만드는 기능은 이번 범위에 없음.

### 2.5 디자인 근거 자료

- 공식 로고·용지 사진·스크린샷·추첨 방송 자료를 사용하지 않았습니다.
- 시안 링크(Claude Artifact, 비공개): 별도로 전달.

## 4. 확인하지 못한 쟁점 (외부 법률 검토가 필요한 부분)

1. **복권 및 복권기금법 핵심 조문 본문** — 웹 도구로 현행 조문 전체를 추출하지 못해, 이용자에게 번호 생성 비용을 받지 않으며 사이트는 광고 수익화를 계획하는 이 서비스가 이 법의 규율 대상에 해당하는지 여부를 조문 원문 기준으로 확정하지 못했습니다.
2. **상표권** — "로또"라는 명칭 자체, 유사 로고·서체 조합에 대한 상표 등록 현황을 검색·확정하지 않았습니다.
3. **부정경쟁방지법상 출처 혼동 가능성** — 최종 시안(색상·서체·레이아웃)이 실제로 일반 소비자에게 동행복권과 혼동을 일으킬 수 있는지는 시안을 본 법률 전문가의 판단이 필요합니다. 면책 문구를 넣었다는 사실만으로 혼동 가능성이 사라진다고 보지 않습니다.
4. **사행성 규제 일반** — 금전·경품 지급이 전혀 없는 설계입니다. 2026-10-02부로 "가상 금액(원)" 표기 자체를 제거하고 순수 줄 수 선택으로 단순화해 이 쟁점의 소지를 줄였으나, 이는 설계상 완화 조치일 뿐이며 규제 기관·플랫폼 정책상 문제 소지가 완전히 해소됐다는 법적 결론은 아닙니다.
5. **약관·개인정보** — 공유 링크 기능(URL fragment 방식)이 개인정보 보호법상 별도 고지 의무를 발생시키는지 여부는 검토하지 않았습니다(다만 설계상 서버 저장 없음).

## 5. 하루콕의 위험 완화 조치 (참고용 — 법적 결론 아님)

- (2026-10-02 추가) "가상 금액(원)" 표기 자체를 제거하고 순수 줄 수(1~5줄) 선택으로 단순화 — 돈을 연상시키는
  표현을 아예 쓰지 않는 방향의 추가 완화 조치이며, 이 역시 법적 결론이 아니라 위험을 줄이는 설계 선택임.

**판단 한계**: 위 조치들은 위험을 줄이는 방향의 설계 선택일 뿐이며, 최종 화면이 실물과 충분히 구별되는지, 상표·부정경쟁방지법·복권 관련 법령을 저촉하지 않는지는 이 문서만으로 확정할 수 없습니다. 최종 시안(디자인 링크 포함)과 이 기능 명세를 근거로 전문 법률 검토 또는 권리자 확인을 받은 뒤 공개 여부를 결정해야 합니다.
