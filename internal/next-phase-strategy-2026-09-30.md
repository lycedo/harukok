# 하루콕 후속 개선 전략 및 구현 경계

작성일: 2026-09-30. 리뷰·계획 문서이며 사이트 코드 변경 아님.

## 우선순위와 합의

이 문서는 이전 content-improvement-plan-2026-09-30.md의 후속 지시서다. 기존 삭제 정비 결과는 유지하되, 음식 통합 복원과 영화 조건부 복원은 예외로 한다. 로또는 보존만 하던 단계에서 묶음 생성·공유 개선 단계로 전환한다. 전면 복원이나 추가 대량 삭제는 하지 않는다.

목표: 실제 유입이 있는 로또를 보존하고, 생활 선택과 계산의 실용성을 높인다. 애드센스 승인이나 법적 무위험을 보장하지 않는다. 구현은 Claude가 수행하고 리뷰 담당자는 사이트 코드를 수정하지 않는다. 커밋·푸시·배포는 별도 지시 전까지 하지 않는다.

## 1. 공개 범위

- 현재 보존한 도구 9개와 가이드 본문 6편을 유지한다.
- 점심·저녁·야식·카페 음료는 기존 데이터로 하나의 메뉴 선택 도구로 통합 복원한다.
- 영화는 장르 뽑기 대신 실제 작품 추천으로 설계한다. API의 상업 이용 조건·비용·출처 표시·데이터 범위를 확인하고 운영자가 수용한 뒤 연동한다. 미확정이면 공개 범위에서 제외하고 다른 개선은 진행한다.
- 음식 추가 후 도구 10개, 영화까지 준비되면 11개다. 가이드 목록 페이지는 본문 6편과 별도로 유지한다.

## 2. 로또 — 무료 번호 메모, 실제 복권 판매가 아님

### 조사 결과와 법적 판단의 한계

- 동행복권 공식 소개에서 1게임 1,000원, 1~45 중 6개 규칙을 확인했다: https://www.dhlottery.co.kr/lt645/intro
- 한국저작권위원회는 아이디어와 그 구체적 표현을 구분한다. 게임 단위·번호 규칙과 공식 복권의 로고·이미지·디자인 복제는 같은 문제가 아니다: https://www.copyright.or.kr/information-materials/common-sense/knowledge-for-netizen/index.do
- 부정경쟁방지법의 출처 혼동 관련 규정도 검토 대상이다. 독자적 디자인과 비공식 표시를 함께 적용한다. 명칭·로고에 대한 상표 등록 검색 및 최종 화면의 침해 여부를 확정한 상태는 아니다: https://www.law.go.kr/LSW/LsiJoLinkP.do?docType=JO&joNo=000200000&languageType=KO&lsNm=부정경쟁방지%20및%20영업비밀보호에%20관한%20법률&paras=1
- 복권 및 복권기금법 현행 페이지는 조회했으나 웹 도구에서 현행 핵심 조문 본문이 추출되지 않았다. 이 문서는 무료 생성기를 적법하다고 확인하는 법률의견이 아니다. 실제 복권 발행·판매·구매대행·대가성 경품 지급 기능은 범위 밖이다: https://law.go.kr/LSW/lsInfoP.do?ancYnChk=0&lsId=009632
- Google 게시자 제한의 온라인 도박 정의와 광고주용 Google Ads 정책을 혼동하지 않는다. 게시자 제한은 금전 등의 대가와 현실의 보상, 지역 등 조건을 다룬다. 한국 관련 예외 문구만으로 사이트 전체 승인·법적 허용을 단정하지 않는다: https://support.google.com/publisherpolicies/answer/10437963?hl=en

판단: 돈을 받거나 상품을 지급하지 않는 번호 생성·기록·공유로 제한하고 공식 표현을 복제하지 않는 설계는 위험을 줄이는 방향이다. 다만 '법적으로 문제없음 확인 완료'라고 보고하지 않는다. 실물과 상당히 유사한 디자인을 고집한다면 최종 시안을 바탕으로 권리자 허락 또는 전문 법률 검토가 먼저 필요하다.

### 기능·문구

- 기존 /fun/lotto-generator URL을 유지한다.
- 사용자 최신 요청: 1게임/5게임 버튼 대신 '가상 금액' 1,000원·2,000원·3,000원·4,000원·5,000원 선택을 제공한다. 각각 번호 1·2·3·4·5줄을 생성한다. 선택 영역 가까이에 '무료 놀이용 설정 · 실제 결제 없음'을 항상 표시한다. 가상 금액이 유료 잔액이나 현금 가치가 있는 포인트인 것처럼 구현하지 않는다.
- 금액 선택 → 번호 생성 → 종이 모양의 결과에 선택한 만큼 번호 행 표시 → 이미지 저장/공유 순서다. 결과에는 '가상 금액 3,000원 · 3줄'처럼 가상임과 줄 수를 함께 적는다. 충전·결제·차감 과정은 없다.
- 버튼은 '번호 생성'이다. '구매', '결제', '발권'이라고 표시하지 않는다. 유료 번호 판매·결제·구매대행·상금·공동구매·지분 공유는 구현하지 않는다.
- 각 게임은 1~45의 서로 다른 정수 6개, 오름차순. 묶음에는 1~5번 행을 사용한다. 같은 묶음 안의 동일 조합은 방지하되 일부 숫자의 중복과 과거 기록의 동일 조합은 허용한다. 규칙을 설명한다.
- 기존 {nums,date} 기록을 보존하고 읽을 수 있게 한다. 묶음 기록 구조가 바뀌면 최소한의 호환 처리를 한다.
- 텍스트 복사·이미지 저장·기기 공유 기능에 현재 표시된 묶음 전체를 반영한다.
- 같은 번호를 상대방이 열어보는 공유 링크를 제공한다면 URL fragment에 번호 묶음만 담는 서버 없는 방식을 우선 검토한다. 열람 시 재추첨하지 않는다. 범위·중복·묶음 수를 검증하고 텍스트로 안전하게 렌더링한다. 민감 정보·전체 이용 기록은 포함하지 않는다. 공유된 결과임을 표시하고 방문만으로 기존 기록을 덮어쓰지 않는다.
- 임의 공유 링크별 페이지를 sitemap에 추가하지 않는다. canonical은 기본 생성기 주소로 유지한다.

### 디자인과 공유 이미지

- 하루콕 고유의 종이형 번호 메모로 디자인한다. 밝은 종이, 단정한 행별 숫자, 점선 구분 같은 일반적인 영수증 표현을 사용할 수 있다. 사용자가 첨부한 Urbanbrush 워터마크 이미지는 분위기 참고만 한다. 이미지·벡터·로고·워터마크를 복사하거나 워터마크를 제거하지 않는다. 공식 복권의 로고, 서체 조합, 특유의 인쇄 배치, 문양을 복제하지 않는다.
- 상단은 '하루콕 번호 메모', 행은 1~5번, 하단은 가상 금액과 무료 생성 안내로 구성한다. 실제 복권의 발행/추첨/판매점/당첨금 청구 서식을 재현하지 않는다. 종이 모양 자체가 합법성을 보장하는 것은 아니며 최종 디자인의 혼동 가능성을 확인한다.
- 공식 로고·용지 사진·스크린샷·추첨 방송 자료를 사용하지 않는다. 가짜 판매점·일련번호·검증 바코드·당첨 청구용 QR을 넣지 않는다.
- 화면과 다운로드 이미지·공유 텍스트에 '하루콕 무료 번호 생성 결과 · 실제 복권 아님 · 구매 및 당첨금 청구 효력 없음'을 읽을 수 있게 표시한다.
- 동행복권과 무관한 서비스임을 페이지에서 명확히 알린다. 표시만 붙이면 모방 디자인이 허용된다고 해석하지 않는다.
- AI 당첨 예측, 확률 향상, 당첨 보장 등의 표현을 추가하지 않는다.
- 로또 판매·구매 유도 링크와 제휴 수익 기능은 이번 범위에 없다.

## 3. 전체 도구·전체 가이드 접근

- 홈에 눈에 띄는 '전체 도구 보기'와 '전체 가이드 보기'를 둔다.
- 홈 안의 #all-tools 영역에 현재 공개한 모든 도구를 중복 없이 표시한다. 별도 목록 페이지를 만들기보다 기존 홈의 완전한 목록을 활용한다.
- 공통 내비게이션의 '도구'는 이 전체 목록으로 연결한다. 상단 추천 카드 몇 개만 가리키는 위치로 연결하지 않는다.
- 상단 추천(로또·음식·상장 등)과 전체 목록을 구분한다. 계산기 7개도 전체 목록에서 직접 접근 가능해야 한다.
- /guides/는 본문 6편 전체를 표시한다. 도구와 가이드의 이름·라벨을 구분한다.
- 현재 존재하지 않는 삭제 페이지를 목록에 다시 넣지 않는다. 영화는 준비된 경우에만 목록에 노출한다.
- 기존 #sectionUtility를 사용하는 링크가 있으면 갱신하거나 앵커를 유지하여 끊기지 않게 한다.

## 4. 음식 통합과 영화

- 음식: 시간대/음료, 음식 종류, 먹지 않는 메뉴 제외, 최근 결과 제외, 후보 없음 안내. 데이터 중복·분류 오류를 검토한다. 영양 근거 없이 건강·다이어트·알레르기 안전을 보장하지 않는다.
- 기존 음식 URL은 실제 대응하는 통합 화면으로 연결한다. 과거 음식 기록이 있으면 보존하거나 호환 방식을 설명한다.
- 영화: 첫 범위는 영화. 한국 서비스·장르·상영시간 등을 선택하고 실제 작품 정보와 시청 서비스 확인 경로를 제공한다. 본 작품·최근 추천 제외, 오류/데이터 없음 처리가 필요하다.
- API 데이터 복사로 작품별 얕은 페이지를 대량 생성하지 않는다. 조회한 후보 안에서 선택한다는 점과 공급자 정보의 최신성 한계를 알린다.
- TMDB 상업 이용과 출처 조건은 https://developer.themoviedb.org/docs/faq 확인. 시청 서비스는 https://developer.themoviedb.org/reference/movie-watch-providers 확인. 무료 상업 사용이나 OTT 직접 재생 링크 제공을 가정하지 않는다. 계약·결제는 사용자 결정 사항이다.

## 5. 기존 계산기·가이드

실업급여 안내 보완은 유지한다. 남은 계산기의 적용 가정과 예시, 가이드 6편의 실제 입력 판단 자료를 보강한다. 새 계산기를 추가하지 않는다. 글자 수를 채우거나 이미 검증된 로직을 불필요하게 다시 작성하지 않는다. 기존 내부 문서의 완료되지 않은 항목과 이번 변경을 구분해 기록한다.

## 6. 구현 순서와 검증

1. 로또 화면·공유 카드 시안을 먼저 제시한다. 공식 복권과 혼동 가능성을 확인한 뒤 구현한다. 화면 최종 법률 적합성이 이미 확정됐다고 주장하지 않는다.
2. 전체 도구/가이드 접근을 보완한다.
3. 음식 통합 복원, 기존 콘텐츠 보완을 진행한다. 영화의 조건 확인은 별도로 진행한다.
4. 가상 금액 1,000~5,000원의 1~5줄 대응, 완전 중복 방지, 기록 호환, 저장 이미지·텍스트 일치, 공유 링크의 동일 결과와 잘못된 데이터 처리를 검증한다. 공유 데이터의 유효 묶음 수는 1~5줄이다. 자동으로 다른 사람에게 공유하지 말고 테스트 수신 대상을 임의로 선택하지 않는다.
5. 모바일·데스크톱에서 모든 공개 도구의 목록 접근, 생성·저장·공유 UI, 가이드 접근을 확인한다. 로또 이미지에도 비공식·실제 복권 아님 표시가 보이는지 확인한다.
6. 관련 회귀 테스트와 깨끗한 dist 빌드, 내부 문서 제외를 확인한다. 공개 페이지마다 쓸모 있는 결과와 독립적인 설명이 있는지 검토한다.
7. 로컬 완료 보고 후 사용자 지시에 따라 dev 검증→운영 반영→재신청 판단을 진행한다. 기능 추가 개수·글 수·트래픽 수치를 승인 기준으로 삼지 않는다.
