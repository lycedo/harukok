# 하루콕 콘텐츠 품질 개선 — 리뷰 및 Claude 구현 지침

작성일: 2026-10-02. 검토 기준: 로컬 HEAD `78a1644`, 공개 도구 10개와 가이드 본문 6편.

**목표:** 방문자가 도구에 올바른 값을 넣고 결과를 이해하며 다음 행동까지 결정할 수 있도록 기존 콘텐츠를 보완한다. AdSense 승인 보장은 하지 않는다.

**구현 담당:** Claude. 리뷰 담당자는 이 문서만 작성하고 사이트 코드는 수정하지 않았다. 실행 시 이 문서를 작업별로 진행한다. 사용할 수 있다면 `superpowers:executing-plans`를 적용하되 아래 사용자 지정 범위가 우선한다.

**구조/기술:** 기존 정적 HTML/CSS/JavaScript와 Node 검증 스크립트를 유지한다. 프레임워크·패키지·새 콘텐츠 관리 시스템은 추가하지 않는다.

**선행 명세:** `internal/next-phase-strategy-2026-09-30.md`. 다만 아래 최신 범위가 충돌하는 예전 지시보다 우선한다.

## 1. 결론과 확인 범위

지금 사이트를 전부 저가치라고 평가할 근거는 없다. 상여금 입력 안내, 육아휴직 비교표, 음식 제외 설정, 상장 편집·저장처럼 실제 효용이 있는 내용과 기능이 이미 있다. 반면 계산기 설명과 가이드 사이에 모순이 남아 있고, 일부 글은 계산기 출력을 반복하는 데서 끝나 실제 서류를 어떻게 읽고 입력해야 하는지 충분히 해결하지 못한다.

이번 개선의 중심은 **추가 삭제나 기능 수 늘리기가 아니라 설명의 신뢰성과 사례의 실용성**이다. 반려 통지만으로 Google이 어느 URL 또는 어느 문장 때문에 거절했는지는 알 수 없다. 아래 항목은 확인한 문제 및 개선 권고이지, Google 내부 심사 원인을 확정한 목록이 아니다.

확인한 것:

- 로컬 도구 10개·가이드 6편의 본문과 관련 소스, 홈·가이드 목록·소개·개인정보처리방침.
- 실제 dev 홈에서 전체 도구 10개 및 가이드 6편으로 이동하는 링크가 노출되는 것.
- 실제 dev 육아휴직 계산기에도 아래의 신청·지급 시점 문구가 남아 있는 것.
- Google 콘텐츠 안내, 고용24 육아휴직 안내, 국세청 원천징수 선택 안내, 고용노동부 연차 안내와 일부 문제 대조.

이번 리뷰에서 확인하지 않은 것:

- 모든 계산의 법령 최신성·수치 전수 재검증, 모바일 전 페이지 조작·스크린샷, 광고 실제 배치, 전체 배포 응답 상태.
- dev 배포 SHA와 로컬 HEAD의 완전한 동일성, 운영 harukok.com에 동일 변경이 반영됐는지.
- 실제 이용자 만족도, 최신 Search Console 전체 기간 데이터, Google의 내부 반려 판정 기준.

## 2. 변경 경계

- 도구 10개, 가이드 6편, 기존 공개 URL을 보존한다. 추가 삭제·일괄 noindex·대량 글 생성은 하지 않는다.
- **로또 최신 상태를 보존:** 1~5줄 선택, 번호 메모, 저장·복사·공유, 최근 기록 목록 및 다시 보기 모달. 이전 문서의 가상 금액 선택은 되살리지 않는다.
- 음식 통합·제외 메뉴·기록 이관·구주소 301은 유지한다.
- 영화 추천은 취소하지 않는다. 별도 후속 작업이며 이번 재신청 준비의 필수 기능으로 삼지 않는다.
- 지금은 로컬 수정과 검증까지만 한다. 커밋·푸시·dev/운영 배포·재신청은 별도 사용자 지시를 따른다.
- 날짜를 일괄 최신화하지 않는다. 실제로 다시 확인한 출처·항목에만 확인일을 갱신한다.
- 전문가 검수, 사용자 후기, 실측 급여명세서, 이용자 수를 만들어내지 않는다. 사례는 가상임을 표시한다.
- 소스의 계산식을 그대로 복사한 참조 코드만으로 제도 검증 완료라고 하지 않는다.

## 4. 먼저 고칠 정확성·신뢰성 문제

아래 코드 줄 번호는 리뷰 시점 기준이다. 변경 후에는 해당 문구로 찾는다.

### 작업 A — 육아휴직 신청·지급 안내

대상: `tools/parental-leave-calculator.html`, `guides/parental-leave-monthly-comparison.html`, 필요한 홈/목록 요약.

확인된 문구:

- 계산기 252행: 매월 신청해야 하며 신청한 달에 바로 전액을 받는다는 설명.
- 계산기 136·264행: 사후지급 폐지를 휴직 급여 전체를 한 번에 지급받는 것처럼 설명.
- 가이드는 이미 법정 산정액과 실제 입금 시점이 다르다고 설명하여 두 페이지가 불일치.

- [ ] 고용24 안내에 맞춰 **매월 또는 일괄 신청 가능**으로 수정한다. 사후지급금 폐지와 당월 즉시 입금 보장은 구분한다.
- [ ] 결과를 해당 휴직 개월차의 예상 산정액으로 설명한다. 실제 지급은 신청·자격 확인 등에 따라 달라짐을 짧게 표시한다.
- [ ] FAQ 본문과 JSON-LD를 함께 고친다. 실제 입금 일자를 임의로 정하지 않는다.
- [ ] 가이드에서 순차 사용도 가능하다는 설명을 보존하고, 공통 사용 기간을 달력상 동시 휴직 기간과 혼동하지 않게 고친다.
- [ ] 검수: `그달에 바로`, 의무적으로 `매월 신청해야`, 폐지 때문에 전체 기간을 `한 번에 전액` 받는다는 문구가 남지 않아야 한다. 임금 300만원 일반/특례의 기존 결과를 불필요하게 변경하지 않는다.

### 작업 B — 연차의 대상·정산·사용촉진

대상: `tools/annual-leave-pay-calculator.html`, `guides/annual-leave-guide.html`.

- [ ] 법정 연차의 기본 적용 조건인 상시 근로자 수와 4주 평균 주 소정근로시간 기준을 공식 자료와 대조하여 입력 전 짧게 표시한다. 법정 의무와 별도 계약상 약정은 구분한다.
- [ ] `올해 발생했지만 아직 쓰지 않은 연차`를 곧바로 확정 지급 대상이라고 읽지 않게 한다. 입력은 **수당 정산 대상인 미사용 연차일수**라는 점과 계산기가 발생·소멸·사용촉진의 적법성을 판정하지 않는다는 점을 명시한다.
- [ ] 122·229행 `적극적으로 독려(연차사용촉진제도)`를 수정한다. 단순 권유와 법정 사용촉진 절차는 같지 않다. 사용촉진 후라도 지정 휴가일 전에 퇴직한 사례를 무조건 무보상으로 안내하지 않는다.
- [ ] 가이드의 모든 연차가 발생 후 1년이라는 설명을 검토하고, 1년 미만 근로자의 연차 사용기간 등 예외를 반영한다.
- [ ] `209시간=월 소정근로시간`이라는 단순 명칭은 실제 소정근로시간과 유급주휴를 포함한 환산 시간을 구분하도록 고친다. 이름 정정만으로 산식을 임의 변경하지 않는다.
- [ ] 통상임금을 고정 수당만으로 한정하지 않도록 육아휴직 페이지와 비교하고 최신 공식 근거로 통일한다.
- [ ] 검수: 적용 대상 확인 → 정산 대상 일수 확인 → 금액 환산 순서가 드러나야 한다. 본문/FAQ/JSON-LD 모두 같은 기준이어야 한다.

### 작업 C — 연봉 추정치와 급여명세서 설명

대상: `tools/salary-calculator.html`, `guides/salary-vs-payslip.html`.

- [ ] 가이드 167행의 보험료가 정확하므로 명세서와 대부분 일치한다는 단정을 고친다. 입력 급여에 따른 추정과 기관 신고 기준 금액·정산 등이 반영된 실제 공제를 구분한다.
- [ ] `회사가 선택한 80/100/120%`를 근로자의 선택·신청을 회사가 반영하는 구조로 바로잡는다. 신청 시기를 매년 초로만 한정하는 근거가 없으면 그 제한도 없앤다.
- [ ] 계산기의 월 비과세 입력은 **총 비과세 합계**인데 본문은 20만원 초과 입력 자체가 틀렸다고 설명한다. 식대 한도와 비과세 합계의 한도를 혼동하지 않게 고친다. 다른 비과세 항목은 각 요건을 충족할 때만 포함한다.
- [ ] 제목 아래 `통장에 실제로 들어오는 금액` 대신 가정에 따른 예상액임을 표시한다. 연간 세액 추정/12와 실제 간이세액표 조회값을 구분하는 기존 안내는 보존한다.
- [ ] 4대보험 전부를 일괄적으로 회사가 절반 부담한다는 FAQ는 각 보험의 구조를 확인하여 과도한 일반화를 제거한다.
- [ ] 검수: 가이드·도구에서 동일 입력 예시 금액이 일치하고, 어떤 차이가 세금/보험/회사 공제 때문인지 추적할 수 있어야 한다. 자녀세액공제 등 이미 별도 검증한 로직을 근거 없이 다시 바꾸지 않는다.

### 작업 D — 퇴직금·실업급여·시급의 남은 설명 정리

- [ ] `tools/severance-pay-calculator.html`의 `퇴직 전전연도 미사용분만 포함`이라는 요약과 최신 FAQ/가이드의 지급의무 발생 시점 설명을 대조하고 통일한다. 급여 입력 힌트가 상여금 지급액 전부를 최근 3개월 급여에 더하라는 뜻으로 읽히지 않게 한다.
- [ ] `guides/severance-bonus-input.html`의 이미 실제 지급된 임금만 평균임금에 포함되는 것처럼 읽히는 표현은 체불임금 등을 포함한 공식 기준으로 확인 후 수정한다. 지급 여부만으로 일괄 제외하지 않는다.
- [ ] 퇴직금 계산기가 통상임금 비교를 하지 않는데 결과를 법정 최저금액으로 단정하지 않도록 한다. 지원 범위 밖 안내를 보존한다.
- [ ] 실업급여의 가입기간을 단순히 현재 직장 근속기간과 같은 뜻으로 표시하지 않는다. `1~3년` 등 겹치는 경계는 `1년 이상~3년 미만`처럼 명확히 한다. 계산 로직 경계도 같이 확인한다.
- [ ] 실업급여 기간 입력의 `잘 모르면 92`는 근사치 선택이라는 점을 표시하고, 실제 시작·종료 기간을 서류에서 확인하는 방법을 가이드로 연결한다. 계산기 예시와 가이드 예시에 8시간 가정을 명시한다.
- [ ] 시급 계산기의 최저임금 미달을 근로기준법 위반으로 뭉뚱그린 설명은 적용 법령과 비교 범위를 확인해 고친다. 입력값 환산만으로 법 위반 확정 배지를 만들지 않는다.
- [ ] 시급/주휴수당 계산은 개근 등 자격 조건을 자동 조사하지 않는다는 짧은 가정을 입력 근처에 둔다. 주 15시간 조건은 공식 기준의 4주 평균 등 적용 맥락을 확인한다.

### 작업 E — 개인정보 설명과 실제 공유 기능 일치

## 5. 가이드 6편의 실용성 보강

기존 표·사례·공식 링크를 버리고 새 장문으로 덮어쓰지 않는다. 아래 산출물을 각 글 안에 한 묶음씩 추가하거나 기존 예시를 교체한다. 분량 목표, 키워드 반복, 글 수 목표는 없다.

- [ ] **급여명세서:** 기존 3,500만원 예시를 바탕으로 가상 명세서 표를 만든다. 지급 항목/비과세 여부/계산기 어느 입력란에 넣는지/계산기에 반영되지 않는 공제로 나눈다. 이어서 보험료·소득세·사내 공제 중 차이가 나는 항목을 찾는 확인 순서를 넣는다. 공식 급여명세서나 실측 자료로 위장하지 않는다.
- [ ] **상여금 입력:** A 최근 3개월 임금 + B 상여금 해당분 + C 포함 대상 연차수당 해당분을 한 표에서 입력 총액으로 합산한다. 연간 상여를 A와 B에 중복 넣는 사례와 올바른 입력을 비교한다. C가 불명확하면 0을 정답으로 취급하지 말고 확인할 서류·담당자를 적는다.
- [ ] **실업급여:** 180일 피보험단위기간, 소정급여일수 산정 가입기간, 퇴사 전 3개월 임금 산정 기간을 서로 다른 항목으로 설명한다. 기존 8시간 예시 옆에 6시간 가정 사례 하나를 독립 계산해 하한액 차이를 보여준다. 같은 월급이면 실제로 하한액이 적용되는지 먼저 계산하고, 차이가 없는 조건을 차이가 나는 것처럼 꾸미지 않는다.
- [ ] **육아휴직:** 기존 임금별 표를 유지하면서 부모 한 명은 6개월, 다른 한 명은 3개월 사용하는 사례 하나를 추가한다. 각각 몇 개월차에 어느 제도를 적용하는지 표시하고 동시/순차 사용과 지급 시점은 따로 설명한다. 실제 입금 날짜를 확정한 달력은 만들지 않는다.
- [ ] **최저임금:** 주 40시간 표준 근무의 209시간 설명을 유지한다. 근로계약서에서 확인할 시간·유급휴일·급여 구성 항목을 간단한 순서표로 만든다. 모든 세전 월급을 무조건 209로 나누면 위반 여부가 확정되는 것처럼 안내하지 않는다. 어떤 항목이 최저임금 산입 대상인지 공식 자료로 확인한다.
- [ ] **연차:** 적용 대상이 확실한 가상의 입사일·퇴사일 사례 하나를 정하여 발생한 휴가/사용한 휴가/정산 검토 대상 일수를 나눠 보여준다. 입사일 기준과 회계연도 기준을 섞지 않는다. 애매한 정확히 1년 경계를 대표 사례로 골라 법리 논쟁을 새로 만들지 않는다.

완료 기준: 각 글을 읽고 이용자가 **준비할 자료 → 넣을 값 → 결과 해석 → 추가 확인할 곳**을 찾을 수 있다. 도구 설명을 그대로 복제한 문단은 관련 글로 연결하여 줄인다. 모든 글에 같은 긴 FAQ·면책문을 기계적으로 붙이지 않는다.

## 6. 도구의 결과물 가치와 홈

- [ ] 로또는 현재 기능을 보존한다. `몇 줄이든`처럼 실제 1~5줄 범위를 넘는 표현만 정리한다. 기록 재열람에서 당시 번호가 유지되고, 공유 열람이 재추첨/기록 덮어쓰기를 하지 않는지 기존 검증을 활용한다. 새 확률 분석·유료 번호·실제 용지 복제는 하지 않는다.
- [ ] 음식 FAQ 중 합친 개발 경위·구주소 목록은 필요한 사용자 안내만 남긴다. 제외한 메뉴가 옛 기록에 남는 이유, 후보가 없을 때 해결 방법을 실제 동작대로 짧게 안내한다. 기능 추가는 하지 않는다.
- [ ] 상장에는 자체 작성한 짧은 칭찬 문구 3개와 현재 편집기로 만든 예시 한 개를 사용한다. 저장 후 인쇄하는 실제 방법을 안내하되 직접 확인하지 않은 A4 최적화·고해상도 보장을 쓰지 않는다. 새 템플릿 시스템은 만들지 않는다.
- [ ] 홈의 전체 도구/전체 가이드 버튼과 전 항목 접근을 보존한다. 목적 그룹에서 해당 계산기뿐 아니라 해당 가이드로 가는 짧은 맥락 링크를 제공하되 아래 전체 가이드 목록과 긴 설명을 중복하지 않는다. `3초 만에` 같은 입증하지 않은 일괄 속도 주장은 제거한다.
- [ ] `/guides/` 소개와 카드 요약은 실제 보강한 내용에 맞춘다. 소개 페이지에 전문가 검수를 새로 주장하거나 형식적 작성자 프로필을 지어내지 않는다.

## 8. 영화 추천 후속 작업

합의는 살아 있다. 다만 API를 붙이면 자동으로 고유한 콘텐츠가 되는 것은 아니다.

후속 명세는 실제 작품을 취향·장르·상영시간 등의 조건으로 좁히고, 왜 후보가 되었는지 표시하며, 이미 본 작품을 제외할 수 있는 최소 흐름으로 잡는다. 외부 줄거리·포스터만 무작위 표시하는 데서 끝내지 않는다. API가 제공하지 않는 감상평을 사실처럼 만들어내지 않는다.

TMDB 공식 FAQ는 비상업 이용 무료와 상업 이용 문의를 구분한다. 광고 수익화 사이트에 사용할 라이선스·비용·출처 표시·이미지 권리·OTT 정보 범위가 정해지기 전에는 공개 구현을 하지 않는다. Netflix의 공식 공개 API를 사용할 수 있다고 가정하지 않는다. 현재 10개 도구 품질 개선과 별개로 진행할 수 있으며, 영화 출시를 AdSense 재신청의 필수 조건으로 만들지 않는다.

검토 집중 사항: 잘못된 자격 일반화, 가이드/도구 숫자 불일치, 구체적 조건 없는 예시, 공유 기능과 개인정보 설명 충돌, 모바일에서 읽을 수 없는 표.
