# 색인 회복을 위한 본문 보강 — 2026-11-13

비공개 작업 문서입니다(배포 대상 아님). 사용자가 "요즘 사용자가 들어오지 않는다"고 해 원인을 찾고 고쳤습니다.
같은 날 [페이지 개선](page-improvement-2026-11-13.md)에 이어집니다.

## 무엇이 문제였나

Search Console을 직접 열어 확인한 수치입니다.

| 항목 | 값 |
| --- | --- |
| 최근 28일 | 클릭 16회, 노출 120회 |
| 최근 3개월 | 클릭 89회, 노출 772회 |
| 색인 생성됨 | **30개** |

**사이트맵은 정상이고 Google도 매일 읽고 있습니다.** 주소를 못 찾는 게 아니라, 찾고 나서 색인하지 않기로 한 것입니다.

"발견됨 - 현재 색인이 생성되지 않음" 12개 중 살아 있는 도구 페이지는 이렇습니다.

- `/fun/pet-name-generator` — 본문 135자 (사이트에서 가장 짧음)
- `/fun/watch-picker` — 214자
- `/fun/name-compatibility` — 206자
- `/tools/image-color-picker`, `/tools/image-grid-splitter`, `/tools/mixing-amount-calculator`

가장 얇은 페이지들이 그대로 색인 거부 목록이었습니다. 측정해 보니 **155개 중 101개가 본문 600자 미만**, 26개는 300자 미만이었습니다.

유입이 꺾인 시점도 맞아떨어집니다. 그래프상 10월 24~29일 사이에 떨어졌고, 그 직전 커밋이
`872f4bd` "Prioritize tool access and simplify supporting content"(-1,338줄), `5070140` "Simplify tool flows and remove repeated interface copy"입니다.
화면을 단순하게 만들면서 검색엔진이 읽을 글까지 걷어낸 것이 원인으로 보입니다. 11-10 도구 정리(1000→155)는 이보다 2주 뒤라 원인이 아닙니다.

## 고친 것

### 1. 본문 보강 — 101개 페이지

각 도구의 **실제 구현(HTML + 인라인 스크립트 + 공유 라이브러리)을 읽고** 자주 묻는 질문 4~5개를 썼습니다.
도구 이름에서 유추하지 않고 코드에 있는 값만 적었습니다. 예: 이름궁합은 해시를 101로 나눈 나머지,
메뉴 뽑기는 기록 50건 보관에 화면 표시 6건, 단위 변환기는 1평을 400÷121㎡로 계산.

- 본문 평균 **1,026자**(최소 603자, 600자 미만 0개). 이전에는 101개가 600자 미만.
- `FAQPage` 구조화 데이터를 함께 넣었습니다.
- 넣은 자리는 광고 아래·관련 도구 위이며, 통합 도구에서 다른 기능을 고르면 접힙니다(그 설명은 대표 기능 것이므로).

정확성 확인: 숫자가 들어간 주장 237건 중 225건을 원본 파일에서 직접 찾아 대조했습니다.
나머지 12건은 계산으로 나온 값(3.3058㎡ = 400/121, ROAS 333 = 100/0.3)이라 소수점이 잘려 자동 대조에 걸리지 않은 것입니다.

### 2. 얇은 본문 재발 방지

`scripts/check-seo.js`에 도구 페이지 본문 **최소 600자** 검사를 넣었습니다(`MIN_BODY_CHARS`).
이번 유입 급감이 "화면 단순화"가 글을 지우면서 생긴 일이라, 같은 일이 빌드에서 막히도록 했습니다.
`verify/verify-seo.js`에 본문을 얇게 만드는 변형 테스트도 추가했습니다.

### 3. 데스크톱 광고 468×60 → 300×250

사용자 승인으로 바꿨습니다. 대시보드 기준 300×250의 CPM이 468×60의 약 2.6배였습니다.
다만 그 수치는 지금은 없는 긴 가이드 글에서 나온 것이라 **같은 성적이 재현된다는 보장은 없습니다.**

- `ad-banner-isolated.js`: 넓은 화면(468px 이상)은 300×250, 좁은 화면은 320×50 유지, 320px 미만은 표시 안 함.
- `ad-frame.html`의 300×250 광고 단위 키는 이미 있던 것이라 새로 추가한 것은 없습니다.
- 자산 버전을 `?v=20261113-rect`로 올려 캐시를 갱신했습니다.
- `privacy.html`의 광고 크기 설명을 300×250으로 맞췄습니다(같은 날 고친 문장이라 다시 손봤습니다).

### 4. 물감 배합 계산기 광고 위치

`/tools/paint-color-mixer`만 광고가 결과와 저장 버튼 **사이**에 있었습니다(커밋 `051b800`에서 의도된 배치).
60px일 때는 괜찮았지만 250px이 되면 저장 버튼을 한참 밀어내고, 버튼을 찾던 사람이 광고를 누르기 쉽습니다.
운영 원칙("화면 가림·클릭 유도를 추가하지 않는다")에 맞춰 다른 154개와 같은 자리(조작부 아래)로 옮기고,
`verify/verify-paint-recipe.js`의 순서 단언을 새 의도로 바꿨습니다.

## 작업 중 발견한 것 (고치지 않음)

도구 코드를 읽다 나온 사실들입니다. 이번 작업 범위가 아니라 글에만 반영하거나 남겨 두었습니다.

- `/tools/image-metadata-stripper` — JPEG를 넣어도 결과는 항상 PNG라 용량이 커질 수 있습니다. 위치·촬영정보 제거 자체는 정상 동작(캔버스 재인코딩)입니다.
- `/tools/pdf-crop-pages` — CropBox만 바꾸므로 잘려 보이는 부분이 파일에는 남습니다. 개인정보 가리기 용도로는 부적합하며, 이 점을 FAQ에 썼습니다.
- `/tools/hash-generator` — 기존 참고 문구가 "파일 해시·HMAC 지원하지 않습니다"인데 통합 후 두 기능이 생겨 문구가 낡았습니다.
- `/tools/images-to-pdf-file` — 참고 문구가 "PNG 결과"라고 말하지만 결과는 PDF입니다(내부적으로 PNG로 재인코딩은 맞음).
- `/tools/qr-code-generator` — 파일 입력이 없는데 "파일당 20MB" 안내가 남아 있습니다.
- `/tools/pet-age-calculator` — 고양이와 소형견의 연 환산값이 4로 같아 결과가 항상 동일합니다.
- `/tools/lorem-ipsum-generator` — 무작위가 아니라 36단어 순환이라 결과가 매번 같습니다.
- `/tools/year-end-tax-calculator` — 7,000만원 초과 구간 근로소득세액공제 기울기가 수상합니다(확인 필요).

## 이어서 고친 것 (같은 날)

사용자가 "수정할 게 있으면 계속 고치고, 디자인이 마음에 안 들면 메인도 바꿔도 된다"고 해 이어 작업했습니다.

### 낡거나 틀린 안내 문구 3개

도구 코드를 읽다 찾은 것들입니다. 모두 **사실과 다른 설명**이라 고쳤습니다.

| 페이지 | 전 | 후 |
| --- | --- | --- |
| `hash-generator` | "파일 해시·HMAC …은 지원하지 않습니다" | 통합으로 `file-sha256-manifest`·`hmac-sha1-generator`가 생겼으므로 기능 선택에서 쓰라고 안내 |
| `images-to-pdf-file` | "PNG 결과에는 …" | 결과는 PDF이고 PNG는 중간 단계임을 밝힘 |
| `qr-code-generator` | "파일당20MB·전체50MB" | 이 페이지는 `files: null`이라 파일 입력이 없음. 실제 한도인 UTF-8 1,000바이트와 SVG 결과로 교체 |

QR 안내는 공유 UI(`HarukokNative1000UI.mount`)가 다시 그리지 않는지 브라우저에서 확인했습니다. 문구가 그대로 남습니다.

### 연말정산 계산기 — 고치지 않았습니다

하위 에이전트가 7,000만원 초과 구간의 `×0.5` 기울기를 "버그 같다"고 보고했는데, **확인해 보니 법 그대로였습니다.**
소득세법 제59조 근로소득세액공제 한도는 7,000만원 초과 구간에서 `66만원 − (총급여−7,000만)×1/2`, 하한 50만원입니다.
총급여 7,032만원이면 이미 하한에 닿는 것이 맞습니다. 종합소득세 과세표준 구간·누진공제액(1,400만 6%, 5,000만 15%/126만, 8,800만 24%/576만, 1.5억 35%/1,544만, 3억 38%/1,994만, 5억 40%/2,594만, 10억 42%/3,594만, 초과 45%/6,594만)도 모두 현행과 일치합니다.
**맞는 계산기를 틀리게 바꾸지 않았습니다.**

### 홈 화면 — 넓은 화면에서 펼치기

`.wrap`이 640px에 묶여 있어 1280px 화면에서 절반이 비고, 도구 155개를 보려면 5,541px(약 6화면)를 내려야 했습니다.
도구 이름도 204px 칸에서 두 줄로 접혔습니다.

`tools/home.css`에만 큰 화면 중단점을 넣었습니다(이 파일은 `index.html`만 불러오므로 도구 페이지는 640px 그대로입니다).

- 1024px 이상: 본문 900px, 분류 4열
- 1320px 이상: 본문 1140px, 분류 5열
- 설명 글과 검색칸은 720px로 묶어 한 줄이 너무 길어지지 않게 함

공통 CSS가 뒤에 실려 `.wrap{max-width:var(--col)}`이 이기므로 `body .wrap`으로 우선순위를 올렸습니다.
(원래 `home.css`의 `.wrap{max-width:720px}`도 같은 이유로 적용되지 않고 있었습니다.)

1440px에서 분류 5열·본문 1140px·페이지 높이 5,033px, 1100px에서 4열·900px, 375px에서는 이전과 동일합니다. 가로 넘침 없음.
분류 필터와 검색, 메이슨리 재배치(ResizeObserver)가 넓은 폭에서도 동작하는 것을 눌러 확인했습니다.

## 홈 "나열된 느낌" 줄이기 + 세로 광고 (같은 날)

사용자 요청: "메인화면에 도구가 너무 나열된 느낌이 있다. 그 느낌을 없애고, 사이드 세로 광고도 넣어도 될 것 같다."

### 무엇이 "나열"로 보였나

분류 카드 안에서 도구 링크가 **모두 같은 폭의 알약**으로 세로로만 쌓여 있었습니다.
155개가 전부 같은 모양·같은 폭이라 눈에 띄는 리듬이 없어 표처럼 읽혔습니다.

### 고친 방법

1. **분류마다 아이콘**(🎲 추첨·만들기, 💰 월급, 🖼️ 사진 편집 …) 14개를 제목에 넣고, 제목 아래에 가는 구분선을 뒀습니다.
2. **링크를 이름 길이대로 흘려 배치**했습니다(`flex-wrap`). "사진 자르기 / 사진 회전·뒤집기"처럼 짧은 것끼리 한 줄에 묶여 줄 끝이 들쭉날쭉해지고, 표 느낌이 사라집니다.
3. 분류 열을 **3열(1320px)·4열(1560px)**로 줄여 칸을 넓혔습니다. 칸이 좁으면(216px) 흘림 배치가 소용없어 한 줄에 하나씩만 들어갔습니다.
4. 카드에 옅은 그림자를 주고 테두리를 얇게 했습니다.

글자 크기는 **16px를 유지**했습니다. 15px로 줄이면 페이지가 더 짧아지지만(4,447px) 디자인 기준의 "초등학생도 쓸 수 있는 크기"와 어긋나, 대신 알약 안쪽 여백을 줄였습니다. 결과 5,038px(원래 5,541px).

### 세로 광고 160×600

- Adsterra에 **160×600 단위를 새로 만들었습니다**(사용자 승인 후). 단위 ID 32253419, 상태 Active.
  기존 단위는 300×250·320×50·468×60 세 개뿐이라 세로형이 없었습니다.
- `ad-frame.html`에 `160x600` 키를 등록하고, `ad-banner-isolated.js`가 `ad-rail-slot`을 160×600으로 띄우도록 했습니다.
- 자리는 **1320px 이상에서만** 나옵니다. 그 아래에서는 CSS로 숨기고, 슬롯 폭이 160px 미만이면 스크립트가 부모를 `hidden` 처리합니다.
- 본문 오른쪽 **별도 열**에 `position:sticky`로 둡니다. 본문이나 푸터를 덮지 않는 것을 좌표로 확인했습니다(1600px에서 광고 왼쪽 1323 > 본문 오른쪽 1295).
- 모바일 배너(320×50)는 그대로입니다. 팝업·자동 이동·화면 가림은 추가하지 않았습니다.

홈은 이제 광고가 둘(본문 300×250 + 옆 160×600)입니다. 도구 페이지는 하나 그대로입니다.

### 검사 보강

`verify/verify-ad-banner.js`의 모의 객체가 `classList.contains`를 **무조건 같은 값으로 돌려주고** 있어 띠·사각형·세로 띠를 구분하지 못했습니다.
클래스 이름을 그대로 넘기도록 고치고, 세로 띠 구간(160px 미만 숨김, 그 위 160×600)과 홈만 배너 2개라는 규칙을 단언에 추가했습니다.

### 검증

검사 37종 통과, 콘솔 오류 없음.
1200px: 본문 900·4열·세로 광고 없음 / 1400px: 본문 1140·본문열 952·3열·세로 광고 160×600 / 1600px: 본문 1380·4열 / 375px: 이전과 동일, 세로 광고 숨김·320×50 유지.
모든 폭에서 가로 넘침 없음. 분류 필터와 검색(퍼센트 → 4건) 동작 확인.

### 배포 직후 잡은 문제 — 세로 광고가 안 떴다

운영에 올린 뒤 확인하니 `.ad-rail`이 `hidden` 처리돼 광고가 아예 붙지 않았습니다.

원인: `ad-banner-isolated.js`는 문서를 읽는 도중(인라인 `<script>` 위치에서) 바로 실행되는데,
그 시점에 `.wrap`의 격자 배치가 끝나지 않아 `slot.clientWidth`가 **0**으로 나왔고, 스크립트가 "자리가 좁다"고 보고 숨겼습니다.
본문 띠 배너는 일반 흐름 안의 블록이라 폭이 바로 정해져 문제가 없었습니다.

로컬 미리보기에서는 같은 코드가 정상 동작했습니다. 타이밍에 따라 갈리는 경쟁 상태였던 것이라,
첫 시도로 `.ad-rail-slot{width:160px}`을 넣었지만 **운영에서는 여전히 숨겨졌습니다**. 부모가 격자 항목이라 그 폭이 정해지기 전에는 자식 폭도 0이었기 때문입니다.

해결: 세로 띠에 한해 자리를 재지 않고 **CSS와 같은 기준(`matchMedia('(min-width:1320px)')`)으로 창 너비만 봅니다**. 문서를 읽는 중에도 값이 확정되는 판단입니다.
폭 명시(`width:160px`)는 배치가 흔들리지 않도록 남겨 뒀습니다.
1440px에서 160×600 정상 로드(본문과 겹치지 않음), 1200px·375px에서는 예정대로 숨김을 확인했습니다.

덧붙여, 처음 운영 확인에서 옛 화면이 보였던 것은 **Cloudflare 엣지 캐시**가 이전 HTML을 내주고 있었기 때문입니다(`?cb=`를 붙이면 새 화면). 캐시를 비우지 않으면 방문자에게도 한동안 옛 화면이 보일 수 있습니다.
