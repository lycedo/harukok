# 색인 회복을 위한 본문 보강 — 2026-11-13

비공개 작업 문서입니다(배포 대상 아님). 사용자가 "요즘 사용자가 들어오지 않는다"고 해 원인을 찾고 고쳤습니다.
같은 날 [페이지 개선](page-improvement-2026-11-13.md)에 이어집니다.

## 무엇이 문제였나

Search Console을 직접 열어 확인한 수치입니다.

| 최근 28일 | 클릭 16회, 노출 120회 |
| 최근 3개월 | 클릭 89회, 노출 772회 |

**사이트맵은 정상이고 Google도 매일 읽고 있습니다.** 주소를 못 찾는 게 아니라, 찾고 나서 색인하지 않기로 한 것입니다.

"발견됨 - 현재 색인이 생성되지 않음" 12개 중 살아 있는 도구 페이지는 이렇습니다.

- `/fun/pet-name-generator` — 본문 135자 (사이트에서 가장 짧음)
- `/fun/watch-picker` — 214자
- `/fun/name-compatibility` — 206자
- `/tools/image-color-picker`, `/tools/image-grid-splitter`, `/tools/mixing-amount-calculator`

가장 얇은 페이지들이 그대로 색인 거부 목록이었습니다. 측정해 보니 **155개 중 101개가 본문 600자 미만**, 26개는 300자 미만이었습니다.

유입이 꺾인 시점도 맞아떨어집니다. 그래프상 10월 24~29일 사이에 떨어졌고, 그 직전 커밋이
`872f4bd` "Prioritize tool access and simplify supporting content"(-1,338줄), `5070140` "Simplify tool flows and remove repeated interface copy"입니다.
화면을 단순하게 만들면서 검색엔진이 읽을 글까지 걷어낸 것이 원인으로 보입니다. 11-10 도구 정리(1000→155)는 이보다 2주 뒤라 원인이 아닙니다.

## 고친 것

### 1. 본문 보강 — 101개 페이지

각 도구의 **실제 구현(HTML + 인라인 스크립트 + 공유 라이브러리)을 읽고** 자주 묻는 질문 4~5개를 썼습니다.
도구 이름에서 유추하지 않고 코드에 있는 값만 적었습니다. 예: 이름궁합은 해시를 101로 나눈 나머지,
메뉴 뽑기는 기록 50건 보관에 화면 표시 6건, 단위 변환기는 1평을 400÷121㎡로 계산.

- 본문 평균 **1,026자**(최소 603자, 600자 미만 0개). 이전에는 101개가 600자 미만.
- `FAQPage` 구조화 데이터를 함께 넣었습니다.
- 넣은 자리는 광고 아래·관련 도구 위이며, 통합 도구에서 다른 기능을 고르면 접힙니다(그 설명은 대표 기능 것이므로).

정확성 확인: 숫자가 들어간 주장 237건 중 225건을 원본 파일에서 직접 찾아 대조했습니다.
나머지 12건은 계산으로 나온 값(3.3058㎡ = 400/121, ROAS 333 = 100/0.3)이라 소수점이 잘려 자동 대조에 걸리지 않은 것입니다.

### 2. 얇은 본문 재발 방지

`scripts/check-seo.js`에 도구 페이지 본문 **최소 600자** 검사를 넣었습니다(`MIN_BODY_CHARS`).
이번 유입 급감이 "화면 단순화"가 글을 지우면서 생긴 일이라, 같은 일이 빌드에서 막히도록 했습니다.
`verify/verify-seo.js`에 본문을 얇게 만드는 변형 테스트도 추가했습니다.

### 3. 데스크톱 광고 468×60 → 300×250

사용자 승인으로 바꿨습니다. 대시보드 기준 300×250의 CPM이 468×60의 약 2.6배였습니다.
다만 그 수치는 지금은 없는 긴 가이드 글에서 나온 것이라 **같은 성적이 재현된다는 보장은 없습니다.**

- `ad-banner-isolated.js`: 넓은 화면(468px 이상)은 300×250, 좁은 화면은 320×50 유지, 320px 미만은 표시 안 함.
- `ad-frame.html`의 300×250 광고 단위 키는 이미 있던 것이라 새로 추가한 것은 없습니다.
- 자산 버전을 `?v=20261113-rect`로 올려 캐시를 갱신했습니다.
- `privacy.html`의 광고 크기 설명을 300×250으로 맞췄습니다(같은 날 고친 문장이라 다시 손봤습니다).

### 4. 물감 배합 계산기 광고 위치

`/tools/paint-color-mixer`만 광고가 결과와 저장 버튼 **사이**에 있었습니다(커밋 `051b800`에서 의도된 배치).
60px일 때는 괜찮았지만 250px이 되면 저장 버튼을 한참 밀어내고, 버튼을 찾던 사람이 광고를 누르기 쉽습니다.
운영 원칙("화면 가림·클릭 유도를 추가하지 않는다")에 맞춰 다른 154개와 같은 자리(조작부 아래)로 옮기고,
`verify/verify-paint-recipe.js`의 순서 단언을 새 의도로 바꿨습니다.

## 작업 중 발견한 것 (고치지 않음)

도구 코드를 읽다 나온 사실들입니다. 이번 작업 범위가 아니라 글에만 반영하거나 남겨 두었습니다.

- `/tools/image-metadata-stripper` — JPEG를 넣어도 결과는 항상 PNG라 용량이 커질 수 있습니다. 위치·촬영정보 제거 자체는 정상 동작(캔버스 재인코딩)입니다.
- `/tools/pdf-crop-pages` — CropBox만 바꾸므로 잘려 보이는 부분이 파일에는 남습니다. 개인정보 가리기 용도로는 부적합하며, 이 점을 FAQ에 썼습니다.
- `/tools/hash-generator` — 기존 참고 문구가 "파일 해시·HMAC 지원하지 않습니다"인데 통합 후 두 기능이 생겨 문구가 낡았습니다.
- `/tools/images-to-pdf-file` — 참고 문구가 "PNG 결과"라고 말하지만 결과는 PDF입니다(내부적으로 PNG로 재인코딩은 맞음).
- `/tools/qr-code-generator` — 파일 입력이 없는데 "파일당 20MB" 안내가 남아 있습니다.
- `/tools/pet-age-calculator` — 고양이와 소형견의 연 환산값이 4로 같아 결과가 항상 동일합니다.
- `/tools/lorem-ipsum-generator` — 무작위가 아니라 36단어 순환이라 결과가 매번 같습니다.
- `/tools/year-end-tax-calculator` — 7,000만원 초과 구간 근로소득세액공제 기울기가 수상합니다(확인 필요).
